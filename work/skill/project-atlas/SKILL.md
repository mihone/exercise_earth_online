# project-atlas — 项目分层代码地图

用户请求参数：**{query}**（可能为空、或为一个业务功能名，例如"订单创建"、"发送出行通知"）

## 执行前提

- 只针对 **Java 项目**（Maven / Gradle 均可）。
- 产出统一落地到项目根目录下的 `project-atlas/`：
  ```
  <项目根>/project-atlas/
  ├─ project.md               # L1 项目全景 + L2 功能清单
  └─ features/
     └─ <功能名>.md            # 单个功能的 L3 分析
  ```
- 落地前先确保 `project-atlas/` 目录存在（不存在则创建）。
- **详细模板、清单、写作规范一律见 [reference.md](reference.md)**，本文件只描述流程。

## 模式路由

- `{query}` **为空** → 走「项目级流程」，产出 `project.md`
- `{query}` **是功能名** → 走「功能级流程」，产出 `features/<功能名>.md`
  - 若 `project.md` 不存在，先提示："建议先跑一次 `/project-atlas` 生成项目地图，是否立即生成？" 用户拒绝则直接就地探明入口。

## 项目级流程（产出 project.md）

### Phase 1：探索

用 Explore agent 做全面扫描。**参考 prompt 见 reference.md「Explore prompt 模板」**。需要拿到：

- 目录结构、模块划分、模块间依赖
- 各模块顶层包一句话职责
- 对外入口注解全清单（详见 reference.md「入口注解清单」）
- 根 `README.md` / `CLAUDE.md` 中的业务背景
- 若能识别，抓 3-5 条**关键设计约束**（判断标准见 reference.md「关键设计约束怎么识别」）

**禁止**全盘 `find /` 或 `mdfind`，只在项目根目录内检索。

### Phase 2：功能清单归纳

基于 Phase 1 的入口 + 包名 + 类名，按 reference.md「L2 归纳规则」把入口聚合成业务功能。

### Phase 3：写入 project.md

按 reference.md「project.md 模板」组织内容。关键章节：项目画像 → 模块分层 → **关键设计约束**（3-8 条，识别到几条列几条）→ 对外入口清单 → L2 功能清单（按模块/业务域分组）→ **业务链路图**（跨功能异步调用链）。

### Phase 4：自检

按 reference.md「Phase 4 自检清单」逐条过。

## 功能级流程（产出 features/<功能名>.md）

### Phase 1：定位功能入口

- 从 `project.md` 的 L2 清单找匹配项。匹配策略（模糊命中/多命中处理）见 reference.md「功能名匹配策略」。
- 无匹配则做多路搜索：中文关键字、领域实体 + 动作、MQ 主题、Apollo key、SOA 接口名。
- 定位到 1~N 个入口后向用户确认唯一。

### Phase 2：主流程调用链 + 隐藏关联扫描

- **调用链深度控制**：见 reference.md「深度控制清单」。
- **隐藏关联扫描**：对 reference.md「隐藏关联完整清单」里的每一类做专门检索，别只依赖调用链。**这一步不能省，是老人改需求最关心的部分**。
- 独立搜索任务用多个 Explore agent 并发。

### Phase 3：写入 features/<功能名>.md

按 reference.md「features md 模板」组织内容。关键章节：**TL;DR（含"最容易踩的 3 个坑"）** → 主流程调用链 → 隐藏关联（问题→解法→影响面三段式） → 关键分支 → 数据与外部依赖 → **修改指引**（按需求类型映射到改动点）。

### Phase 4：自检

按 reference.md「Phase 4 自检清单」逐条过，重点校验老人视角两条：
- 每条隐藏关联是否给出了明确的"影响面"，而不是仅存在性描述
- 修改指引里的需求类型 → 改动点，是否真能定位到具体 file:line

## 已存在文件的处理

无论项目级还是功能级：

1. **先读现有文件**。
2. **保留手动补充块**：识别 `<!-- manual -->` … `<!-- /manual -->` 标记之间的内容，原样保留不覆盖。
3. **补缺 + 修正**：缺失章节按当前扫描补齐；发现错描述则修正，并在被修正处加一行：
   > _[修正 YYYY-MM-DD] 原描述为 "..."，实际代码位于 `AaaService#bbb`，已更正。_
4. **更新末尾时间戳**（今日日期来自环境，不用 `Date.now()`）。

## 探索纪律

1. **失败超过 2-3 次必须停止并汇报**：任何 grep / read / 定位失败连续 3 次，停下向用户报告失败原因和推测。
2. **不要全盘搜索**：所有搜索限定在项目根目录内。
3. **深度节制**：调用链追到"外部边界"就停，别追进 `StringUtils.isNotBlank` 这类工具类。
4. **file:line 必须准**：给出的行号必须能直接跳转，别给"大致位置"。
5. **善用并发**：注解扫描、多主题搜索用多个 Explore agent 并发（一条消息多个 tool call）。

## 输出纪律

生成完文件后，在对话里给用户一个**极简摘要**：
- 写到了哪个文件（绝对路径）
- 关键结论 3-5 条（例："发现 2 个隐藏 AOP 切面"、"Apollo 开关 xxx 会短路主流程"、"发现 3 个可能踩坑点"）
- **不要**把整个 md 文件内容再贴回对话。
